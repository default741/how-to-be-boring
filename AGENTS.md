# AGENTS.md

## Project Snapshot

- This repo is a personal portfolio built with Next.js 16 App Router, React 19, TypeScript, and Tailwind CSS.
- Deployment target is GitHub Pages, not a long-running Node server. `next.config.mjs` uses `output: 'export'`, `basePath: '/how-to-be-boring'`, and `images.unoptimized: true`.
- The root `README.md` is still the default create-next-app template and is not a reliable description of the current app.

## Commands

- `npm run dev`: start the local preview.
- `npm run build`: primary validation step. Run this after route, metadata, content, or styling changes.
- `npm run start`: available, but deployment is based on the static export generated by the build.
- There is currently no dedicated test or lint script in `package.json`.

## Architecture

- Routes live under `src/app/**`.
- The shared shell, global metadata, fonts, CSP, and theme provider live in [src/app/layout.tsx](src/app/layout.tsx).
- Shared site UI lives in `src/components/site/**`; theme components live in `src/components/theme/**`.
- Shared page sections commonly use [src/components/site/PageIntro.tsx](src/components/site/PageIntro.tsx) and the `panel` / `btn` utility classes defined in [src/styles/globals.css](src/styles/globals.css).
- Structured page content is stored in `src/data/**`.
- Blog source files live in `content/posts/**`, are parsed in [src/lib/blog.ts](src/lib/blog.ts), and are rendered with `next-mdx-remote/rsc` plus `remark-gfm` in [src/app/blog/[slug]/page.tsx](src/app/blog/[slug]/page.tsx).
- Site-level URL helpers and deployment config live in [src/lib/site.ts](src/lib/site.ts).

## Conventions For Agents

- Use the `@/*` import alias from `tsconfig.json` instead of long relative paths.
- For internal links, canonical URLs, social image URLs, and asset URLs that must work after deployment, use `withBasePath()` or `absoluteUrl()` from [src/lib/site.ts](src/lib/site.ts). Do not hardcode root-relative production paths.
- If you generate asset URLs from filenames, encode the filename segment first. Some award/certificate filenames contain spaces.
- Keep the current editorial visual direction: light theme is the default, display typography comes from the serif font in [src/app/layout.tsx](src/app/layout.tsx), and shared surface styling comes from [src/styles/globals.css](src/styles/globals.css). Prefer extending existing primitives over introducing a new visual system.
- Navigation is data-driven through `primaryNavigation`; update the navigation source rather than editing desktop and mobile menus separately.

## Static Export Constraints

- Avoid adding features that require a persistent server at runtime unless the user explicitly wants to change the deployment model.
- Build-time filesystem reads are acceptable for local content, as shown by the blog loader in [src/lib/blog.ts](src/lib/blog.ts).
- Remember that Next image optimization is disabled for deployment, so image handling should assume static files.

## High-Value Validation

- After route or metadata changes, run `npm run build` to catch export-time issues.
- After navigation changes, check both desktop and mobile menu behavior because the header renders different layouts by breakpoint.
- After changing page-level assets, verify the final URLs include the GitHub Pages base path.
